# NYCTaxiDash — NYC 택시 트래픽 대시보드 리뉴얼 설계

날짜: 2026-08-21 · 상태: 사용자 승인 (브레인스토밍 완료)

## 배경과 목적

- 포트폴리오 4개 카드 중 dash(데이터시각화 기말 과제)가 가장 빈약 — 채용 담당자가 가장 쉽게 클릭하는 라이브 데모이므로 개선 효과 최대.
- 목표: "NYC 택시는 언제, 어디서 막히는가"에 답하는 분석 리포트형 인터랙티브 대시보드. 통계 전공자다운 정직한 집계 + Claude Code 페어링(바이브 코딩) 역량의 간접 증명.
- 기존 `dash` 리포는 그대로 보존. **신규 리포 `HollyRiver/NYCTaxiDash`**에 빌드, GitHub Pages 배포 (`hollyriver.github.io/NYCTaxiDash/`).
- 완성 후 포트폴리오 카드·프로필 README의 대시보드 링크를 신규 리포로 갱신 (별도 작업).

## 데이터

- 원본: Kaggle NYC Taxi Trip Duration 계열 표본 14,587건 (2016-01 ~ 2016-06), 승하차 좌표·시각·소요시간 포함.
- 링크 소멸 대비 **CSV(1.9MB)를 리포에 동봉**, 출처·라이선스 README 명시.
- 정제(빌드 스크립트): haversine 거리(km)·물리 속력(km/h) 재계산, 이상치 제거(비현실 속력·좌표 이탈·초단시간), 제거 기준 문서화.

## 아키텍처 — 정적 사이트 + 빌드 타임 전처리

```
scripts/build_data.py  (Python, 재현 가능)
  ├─ trips.json        슬림 레코드 전량 (좌표 반올림, dow, hour, speed, dist) → 클라이언트 실시간 재집계용
  └─ flow_{weekpart}_{timeband}.geojson × 8   도로망 통행량 슬라이스
docs/ (GitHub Pages 루트)
  ├─ index.html        대시보드 (MapLibre GL + Plotly.js + 커스텀 JS/CSS)
  └─ data/             위 산출물
```

- 도로 플로우: osmnx로 NYC 도로 그래프 취득 → 트립별 최단경로 → 세그먼트 통행량 집계 → 주중/주말 × 시간대 4구간(새벽/오전/오후/저녁) = 8 슬라이스 GeoJSON. 굵기·밝기 = 통행량. geometry 단순화 + 하위 통행량 컷으로 용량 관리.
- osmnx 실패 시 폴백: 헥스빈 단독 구성으로도 성립하도록 레이어 분리 설계.

## 화면 구성

1. 헤더: 제목, 데이터 기간·표본 수·출처 한 줄.
2. KPI 스트립: 총 트립, 평균 속력, 최저속 시간대 등 3~4개.
3. **메인 지도** (MapLibre GL, 대비 강화 라이트 베이스맵 + Manhattan/Central Park/JFK/LGA 랜드마크 라벨):
   - 레이어 A **도로 플로우**: 주중/주말 × 시간대 슬라이스 전환 (8장, 사전 계산). 임팩트 담당.
   - 레이어 B **헥스빈**: 요일 버튼·시간 슬라이더의 어떤 조합이든 실시간 재집계. 색 = 트립 밀도 ↔ 평균 속력 전환. **표본 수 미달 셀은 반투명** 처리.
4. 컨트롤 바: 요일 7버튼(중복 토글) + 전체 선택/해제, 시간 슬라이더(0–23 + 전체), 지표 전환, 레이어 전환.
5. 보조 차트 (Plotly.js, 지도와 필터 상태 공유): 요일×시간 평균 속력 히트맵, 시간대별 트립 수.
6. 인사이트 노트: 데이터에서 확인된 관찰 3~4개 (명사형 문체).
7. 푸터: 출처·한계(최단경로는 실주행 경로 아님 추정, 2016 표본) + "Claude Code 페어링으로 리뉴얼" 한 줄 + 리포 링크.

## 인터랙티브 범위 (핵심 합의)

| 레이어 | 필터 범위 | 근거 |
|---|---|---|
| 도로 플로우 | 주중/주말 × 4시간대 (8슬라이스 전환) | 세그먼트 GeoJSON이 무거워 168조합 사전계산 불가 |
| 헥스빈 + 보조 차트 | 요일 멀티선택 × 시간 슬라이더 전 조합 | 원본 전량(슬림 JSON)을 브라우저에서 재집계 |
