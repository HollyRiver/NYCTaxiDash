# 한 화면 고정 레이아웃 — 설계

2026-08-25 · 관련: [2026-08-21 원설계](2026-08-21-nyctaxidash-design.md)

## 배경

대시보드 아래에 관찰 4항목(`.notes`)과 데이터·한계 2문단(`.foot`)이 붙어 있어, 분석 텍스트를 읽으려면 스크롤이 필요했다. 지도·차트·텍스트가 한 화면에 같이 보이지 않아 상호 참조가 끊긴다.

## 결정

1. **해설 텍스트를 화면에서 제거하고 README.md를 정본으로 삼는다.** 화면에는 제작·저작권 1줄만 남긴다.
2. **대시보드를 뷰포트 contain-fit 블록으로 만든다.** 비율(`--dash-ratio`)을 고정한 채 뷰포트에 들어가는 최대 크기로 키우고, 남는 세로·가로는 대칭 여백으로 환원한다. 가로가 긴 어떤 출력장치에서도 같은 구도가 유지된다.

### 통계적 정직 유지

데이터 정제 기준과 한계 고지가 화면에서 사라지므로, 푸터 한 줄이 계산 근거를 직접 문장으로 밝힌다.

수치만 보고 나가는 사용자도 "최단 경로 기준"이라는 단서를 한 번은 읽게 되고, 상세 기준과 한계는 GitHub 링크 너머 README가 받는다. KPI 칩의 부가 텍스트("최단 경로")가 같은 고지를 지표 옆에서 다시 반복한다.

## 구조

### 크기 계산 (docs/css/style.css, :root)

```
--chrome  : 대시보드 밖에서 세로를 먹는 총량 (body 상하 패딩 14+14 + 푸터 46) = 74px
--fit-h   : min(100dvh - --chrome, --dash-maxh)      뷰포트가 내줄 수 있는 세로
--dash-w  : min(100%, --maxw, --fit-h * --dash-ratio) 폭
--dash-h  : min(--fit-h, --maxw / --dash-ratio)       폭에서 비율로 역산한 세로
```

`.dash`는 `min-height: var(--dash-h)`를 받는다. **`height`로 확정하면 안 된다** — 짧은 뷰포트에서 그리드 아이템이 상자 밖으로 32px 넘쳐 히트맵이 푸터를 덮는 것을 실측으로 확인했다. `min-height`면 콘텐츠 최소 높이가 더 클 때 상자가 자라 겹침 없이 스크롤로만 넘어간다.

`--dash-w`에는 `100%`가 들어 있어 세로 계산에 재사용할 수 없다(세로 백분율은 컨테이너 높이 기준으로 풀림). `--dash-h`를 따로 두는 이유다.

값: `--dash-ratio: 1.85`, `--dash-maxh: 860px`, `--maxw: 1200px`.

비율 1.85는 짧은 뷰포트에서 우측 패널 폭을 365px 이상으로 유지하기 위해 정해졌다. 그 아래로 좁아지면 시간대 버튼 5개가 3줄로 접혀 컨트롤이 133 → 155px로 커지고, 그만큼 한 화면 하한이 올라간다.

### 세로 분배

`.dash`가 높이를 정하고 양쪽이 잔여 세로를 흡수한다 (기존에는 우측 패널이 높이를 정하고 지도가 따라갔다).

| 블록 | 세로 |
|---|---|
| 지도 `#map` | `flex: 1` — 좌측 잔여 전부 (하한 360px) |
| 컨트롤 `.controls` | 고정 133px (모드 전환 시 차트가 움직이지 않게) |
| 시간대 차트 `#chart-hour` | `flex: 1` — 우측 잔여 전부 (하한 140px) |
| 히트맵 `#chart-heat` | JS가 폭에서 정방 비율로 산정 (하한 120px) |

`.foot`은 `margin-top: auto`로 항상 화면 하단, `.dash`는 `margin: auto`로 남는 세로의 중앙에 놓인다.

### KPI 스트립

순서를 `분석 트립 · 평균 속력 · 평균 이동거리 · 최저속 시간대`로 바꾸고 부가 텍스트를 "최단 경로"로 통일. main.js가 id로 접근하므로 DOM 순서 변경은 무해하다.

**한 줄 유지가 곧 지도 크기다.** 칩이 2x2로 접히면 스트립이 32 -> 69px가 되고 그만큼 지도가 줄어든다. 그래서 칩 여백(`padding: 5px 8px`)·자간(`gap: 6px`)·폰트(라벨 0.7rem, 부가 0.62rem)를 압축해 4개 필요폭을 670 -> 615px로 낮췄다. 1366x625에서 좌측 컬럼 423px 확보 — 압축 전(384px) 대비 +39px.

그래도 안 들어가는 폭대에서는 3+1로 어긋나게 접히므로 `@media (max-height: 618px), (max-width: 1047px)`에서 2x2 그리드로 고정한다. 임계는 실측 필요폭에서 역산했다 (`ref/probe-kpi.mjs`):

```
좌측 컬럼 = 0.62 * (--dash-w - 16) >= 615  ->  --dash-w >= 1008px
  세로 구속: --fit-h >= 1008 / 1.85 = 545  ->  100dvh >= 619px
  가로 구속: 100vw - 40 >= 1008            ->  100vw  >= 1048px
```

라벨 길이나 칩 여백을 바꾸면 필요폭이 달라지므로 두 임계도 함께 재역산할 것.

비율(`--dash-ratio`)을 1.88로 올리면 짧은 뷰포트에서 좌측 컬럼이 10px 넓어져 임계에 여유가 생기지만, 1200px 상한에 걸리는 큰 화면에서 대시보드 세로가 649 -> 638px로 줄어 지도가 오히려 작아진다. 지도를 키우는 것이 원래 목적이므로 1.85를 유지하고 임계를 실측 최소값에 붙였다.

### 리사이즈 대응 (docs/js/main.js)

기존에 리사이즈 핸들러가 없어 `#chart-heat`의 폭 기준 높이가 최초 1회만 계산됐다. 창 크기가 곧 차트 크기가 되는 구조에서는 이게 그대로 드러나므로, 150ms 디바운스 핸들러에서 `sizeHeatBox()` 재계산 + `Plotly.Plots.resize()`를 호출한다. Plotly의 `responsive: true`는 컨테이너 **세로** 변화를 따라가지 않는다.

## 한계

- **뷰포트 세로 632px 미만에서는 스크롤이 생긴다.** 콘텐츠 최소 높이(558px)와 `--chrome`(74px)의 합이 하한이다. 이보다 낮추려면 차트를 읽기 어려운 크기까지 줄여야 해 받아들이지 않았다. 1366x768 창, 1280x720 전체화면 등 일반적인 가로형 출력장치는 모두 하한 위에 있다.
- **모바일(900px 이하)은 한 화면 고정 대상이 아니다.** 세로 스택 + 스크롤로 폴백한다. 별도 설계 과제로 남김.
- 폰트 크기는 스케일하지 않는다. 상자만 줄어들므로 아주 작은 화면에서는 상대적으로 텍스트가 커 보인다.
